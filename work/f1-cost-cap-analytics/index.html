F1 Cost-Cap Compliance Analytics

MS CAPSTONE · SQL SERVER · TABLEAU
MS Capstone · Lewis University

Formula 1’s cost cap gives every constructor the same spending ceiling, so the question worth forecasting isn’t who spent the most, it’s who’s about to hit the wall. On a team SQL/Tableau data layer covering constructor revenue across 11 seasons, I built an ARIMAX time-series model that forecast spend with 5.03% MAPE, then built the Tableau dashboards that let stakeholders actually see where financial constraints were about to meet on-track results.

What I actually built

01

A data layer worth forecasting from

Constructor revenue across 11 F1 seasons went into a shared SQL Server star schema, the foundation the forecasting and the dashboards both had to trust before either was worth building. I validated 1,165 data rows with custom SQL scripts first.

02

Forecasting spend before it happens

I built an ARIMAX time-series model to forecast cost-cap exposure, landing at 5.03% MAPE, accurate enough to flag a constructor approaching the ceiling before the season did.

03

Testing the model that felt fancier, and not trusting it blindly

A neural net was the obvious "impressive" choice, so I benchmarked it against a Random Forest model instead of assuming. The Random Forest won, which is the whole point of benchmarking rather than picking the trendiest option.

04

Dashboards stakeholders could actually read

The forecast only matters if someone acts on it, so I built Tableau dashboards on top of the same data layer, letting stakeholders correlate financial constraints with on-track results at a glance.
